# Coder Agent Sandbox Execution Rules

## Overview
When the Coder Agent uses the `docker_sandbox.py` tool (or any other code execution tool), the LLM must generate **perfectly formatted, raw Python code strings**. 

Because the code is passed directly into a Python `subprocess.run()` via `stdin` or `ast.parse()`, any conversational filler, markdown formatting, or incorrect newline escaping will cause a catastrophic `SyntaxError` (like the "unterminated string literal" bug).

## Strict System Prompt Rules for the LLM

If an LLM is routed to write code for the Sandbox, its system prompt MUST enforce the following constraints:

1. **NO CONVERSATIONAL FILLER:** Do not say "Here is the code" or "I have finished". Output ONLY the code.
2. **NO MARKDOWN BLOCKS:** Do NOT wrap the code in ```python ... ``` tags. The string must be raw and immediately executable by the Python interpreter.
3. **ESCAPE NEWLINES CAREFULLY:** If you are generating a script that generates a document (Code Interpreter pattern), ensure that all `\n` characters are valid within the Python script context.
4. **NO EXTERNAL REQUESTS:** You do not have internet access. Do not `pip install` or `import` anything that is not in the standard library or pre-installed in the custom image (e.g., `pandas`, `python-docx`, `numpy`).

## Example: Perfect Sandbox Input

When generating a Code Interpreter document, the LLM must output exactly this format and nothing else:

```text
from docx import Document
import base64
import io

doc = Document()
doc.add_heading('Custom Report', 0)
doc.add_paragraph('Generated by Agent')

buffer = io.BytesIO()
doc.save(buffer)

b64_str = base64.b64encode(buffer.getvalue()).decode('utf-8')
print("\\n<<<<FILE_START>>>>\\n" + b64_str + "\\n<<<<FILE_END>>>>")
```

*(Notice the absence of conversational text and markdown backticks in the final string passed to the tool, as well as the correct double backslashes for the literal newline prints if necessary based on the orchestrator's JSON formatting).*
